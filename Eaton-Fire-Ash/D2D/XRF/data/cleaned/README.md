# XRF cleaned data — schema and harmonization

This directory contains publication-ready XRF tables for the Eaton Fire ash
study. All four files are regenerated by
`D2D/XRF/scripts/clean_xrf_raw_to_d2d.py` from the raw instrument exports in
`Manuscript/Data/`. Long-format files are the canonical source consumed by
the analysis pipeline (`scripts/01–07`); wide-format files are conveniences
for human readers, supplementary tables, and data deposit.

## Files

| File | Format | Rows | Cols | Purpose |
|------|--------|------|------|---------|
| `xrf_concentrations.csv` | long | 2598 | 8 | FP-derived element concentrations, one row per (sample, method, element) |
| `xrf_concentrations_wide.csv` | wide | 107 | 104 | Same data pivoted; one row per (sample, method); every element gets `<El>_value_ppm` and `<El>_err_ppm` columns (all in ppm) |
| `xrf_intensities.csv` | long | 850 | 6 | Pb L-line emission intensities, one row per (sample, method, line) |
| `xrf_intensities_wide.csv` | wide | 107 | 18 | Same data pivoted; one row per (sample, method); columns for each canonical Pb line `<Line>_cps` and `<Line>_err_cps` |

Sample inventory (cross-platform pairing): see
`sample_id_harmonization.csv` in this directory.

## Conventions

- **`sample_id`** is the canonical primary key. For ash samples it joins to
  ICP-MS measurements via `sample_id == EFA.ID` (the planned ICPMS cleanup
  will rename `EFA.ID` to `sample_id` for parity).
- **`method`** captures the XRF preparation: `pellet` or `powder`. PBP clay
  calibration standards retain the method-embedded form
  (`PBPxx_pellet_A`, `PBPxx_powder_1`) so the calibration registry join in
  `D2D/XRF/data/calibration/PBP_calibration_table.csv` keeps working. When
  ICP-MS is integrated, its `method` field will be `icpms` (or
  `icpms_<digestion>`) so the same long-format schema accommodates both
  instruments.
- **`element`** uses the standard one- or two-character element symbol
  (case-sensitive, e.g., `Ca`, `Fe`, `Pb`). Identical to ICP-MS column
  symbols.
- **`unit`** is one of `ppm` or `%` in the long concentrations file; the
  wide file pre-converts everything to ppm so cross-comparison and
  cross-instrument concatenation are unambiguous.
- **Missing values** are written as the literal `NA`. Do not interpret an
  empty cell as zero. (This is a deliberate change from earlier exports
  where some non-detects were written as `0` or em-dash.)

## Long format column dictionary

`xrf_concentrations.csv`:

| Column | Type | Description |
|---|---|---|
| `sample_id` | string | Sample identifier; joins to `EFA_ICPMS_PPM.csv:EFA.ID` |
| `method` | string | `pellet` or `powder` |
| `element` | string | Element symbol (e.g., `Pb`, `Ca`) |
| `intensity_cps` | float / NA | Net peak intensity in counts per second (when reported by the FP routine) |
| `intensity_err_cps` | float / NA | Counting/fitting error on `intensity_cps` |
| `value` | float / NA | FP-derived concentration |
| `unit` | string | `%` or `ppm` (matches the unit the FP algorithm reported) |
| `value_err` | float / NA | Uncertainty on `value`, in the same unit |

`xrf_intensities.csv`:

| Column | Type | Description |
|---|---|---|
| `sample_id` | string | Sample identifier |
| `method` | string | `pellet` or `powder` |
| `line_symbol` | string | Pb L-line: `Pb_La1`, `Pb_La2`, `Pb_Lb1`, `Pb_Lb2`, `Pb_Lb3`, `Pb_Lb4`, `Pb_Lg1`, `Pb_Ll` |
| `energy_keV` | float | Theoretical line energy |
| `intensity_cps` | float / NA | Net peak intensity (counts per second) |
| `intensity_err_cps` | float / NA | Counting/fitting error |

## Wide format column dictionary

`xrf_concentrations_wide.csv`:

- Keys: `sample_id`, `method`.
- For every element `El` observed in any sample, two columns:
  `El_value_ppm` and `El_err_ppm`. Values are pre-converted to ppm
  regardless of the instrument-reported unit (1 % = 10 000 ppm).

`xrf_intensities_wide.csv`:

- Keys: `sample_id`, `method`.
- For each of the eight canonical Pb lines, two columns: `<Line>_cps` and
  `<Line>_err_cps`.

## Provenance and reproducibility

- Source: `Manuscript/Data/2_XRF-concentrations-raw.csv` and
  `Manuscript/Data/3_XRF-intensities-raw.csv`. These are the
  hand-concatenated raw instrument exports preserved for traceability.
- Cleaning: `D2D/XRF/scripts/clean_xrf_raw_to_d2d.py` performs:
  1. Drop interleaved spurious header rows from the raw concatenation.
  2. Drop empty rows.
  3. Normalize Pb line symbols to ASCII underscore form.
  4. Replace em-dash placeholders with NA.
  5. Restore method infix on PBP calibration sample IDs.
  6. Average byte-identical and slightly-differing replicate measurements
     within `(sample_id, method, element)` (or `…line_symbol`).
  7. Convert wide-format values to ppm.
- Replicate aggregation summary printed by the script:
  - `dedup_byte_identical`: rows that were exact duplicates.
  - `dedup_averaged`: keys whose duplicate rows had small numeric
    differences (4 elements in this dataset, all from sample JPL40).

## Cross-platform downstream

The XRF cleaned tables are designed to bind directly with the ICP-MS data
once that file is cleaned to the same long-format schema:

```
sample_id, method, element, value, unit, value_err
```

After ICP-MS cleanup, a single concatenated long table with a `method`
field (`pellet`, `powder`, or `icpms`) supports every cross-platform
comparison, Bland-Altman analysis, and threshold-classification operation
in the manuscript.
